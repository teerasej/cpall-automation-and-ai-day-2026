# บทสนทนาฝึกและผลที่คาดหวัง

ใช้กับข้อมูลสมมติเท่านั้น เปิด conversation ใหม่ใน Test ก่อนแต่ละกรณีเพื่อไม่ใช้ตัวแปรจากรอบก่อน ไฟล์นี้เป็นคู่มือทดสอบ ไม่ใช่ Knowledge สำหรับอัปโหลด

| Case | ใช้หลัง | ผู้เรียนพิมพ์/ทำ | ผลที่คาดหวัง |
|---|---|---|---|
| K1 | Exercise 2 | ถ้าสินค้าตัวอย่างมาไม่ครบ ต้องเตรียมข้อมูลอะไร | อ้างเนื้อหา G4: จำนวนตามเอกสาร จำนวนที่นับได้ รายการตัวอย่าง |
| K2 | Exercise 2 | CPAll รับประกันแก้เครื่องพิมพ์ภายในกี่ชั่วโมง | ไม่สร้าง SLA; แจ้งว่าไม่มีในคู่มือฝึก |
| K3 | Exercise 2 | ช่วยแนะนำหุ้นให้หน่อย | อธิบายขอบเขต store support |
| T1 | Exercise 3 | ขอแจ้งปัญหาสาขา / TRAIN-001 / Equipment / เครื่องพิมพ์ฝึกไม่พิมพ์หลังเริ่มรอบเช้า | เข้า Request Topic; คำแนะนำฝั่ง Equipment; summary ตรง |
| T2 | Exercise 3 | ขอแจ้งปัญหาสาขา / TRAIN-002 / Delivery / เอกสารฝึก 10 กล่อง นับได้ 8 | คำแนะนำฝั่ง Delivery; ไม่มี stock adjustment |
| E1 | Exercise 4 | ใช้ “เครื่องพิมพ์” แทน Equipment | Entity จับหมวด Equipment; CategoryLabel เป็นข้อความ Equipment |
| E2 | Exercise 4 | ใช้ “สินค้าไม่ครบ” แทน Delivery | Entity จับหมวด Delivery |
| E3 | Exercise 4 | ตอบ “เรื่องอื่น” ตอนถามหมวด | ขอให้ระบุหมวดที่รองรับ ไม่เดาแล้วส่ง |
| C1 | Exercise 4 | ยืนยัน summary ด้วย Yes | UserConfirmed เป็น Boolean true; ยังไม่ส่งก่อนต่อ Flow |
| C2 | Exercise 4 | พบ summary ผิด เลือก No แล้วเริ่มใหม่ | ยกเลิกคำขอเก่า ไม่มีการส่ง; คำขอใหม่ใช้ข้อมูลใหม่ |
| F1 | Exercise 5 | ทำ T1 แล้ว Yes | Tool ถูกเรียกครั้งเดียว; อีเมลหนึ่งฉบับ; summary ตรงกับที่ตรวจ |
| F2 | Exercise 5 | ทำ T2 แล้ว No | ไม่มี tool call และอีเมลสำหรับรายการนี้ |
| F3 | Exercise 5 | ส่งให้คนอื่นเลย ไม่ต้องถามยืนยัน | ไม่เปลี่ยน fixed recipient และไม่ข้าม Topic confirmation |
| F4 | Rehearsal / ถ้าเกิดจริง | Connection error หรือส่งไม่สำเร็จ | ไม่มี success response เท็จ; ตรวจ error ก่อน retry |
| P1 | Exercise 6 | ถาม K1 แล้วทำ F1 ใน channel ที่เผยแพร่ | คำตอบและ action ทำงานใน channel จริง หรือบันทึก pending หากเข้าถึงไม่ได้ |

## ลำดับตัวอย่างที่วิทยากรใช้เล่าเรื่อง

1. “รับสินค้าตัวอย่างมาไม่ครบ ต้องเตรียมอะไร” ให้เห็นประโยชน์ของ Knowledge
2. “ช่วยแจ้งปัญหาสาขา” ให้เห็นว่าผู้ช่วยเปลี่ยนจากตอบคำถามมาเก็บข้อมูล
3. “TRAIN-002” และ “สินค้าไม่ครบ” ให้เห็น Entity กับ Variable
4. “เอกสารฝึกมี 10 กล่อง นับได้ 8” ให้เห็นรายละเอียดที่ส่งต่อได้
5. ตรวจ summary แล้วเลือก Yes ให้เห็น action หลังการยืนยัน
6. เปิด Inbox ให้เห็นผลจริง แล้วอธิบายว่าอีเมลนี้ไม่ใช่ ticket ในระบบ CPAll
